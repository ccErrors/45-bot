# ТЗ: Telegram-бот для записи велозаездов («мини-Strava»)

## 1. Цель

Telegram-бот, который записывает трек поездки по трансляции геопозиции (Live Location)
и по запросу рисует картинку трека на карте OSM с раскраской по скорости.

## 2. Стек

| Компонент  | Решение                                                            |
|------------|--------------------------------------------------------------------|
| Язык       | Go 1.26                                                            |
| БД         | SQLite 3 (`modernc.org/sqlite` — чистый Go, без CGO)               |
| Telegram   | `github.com/go-telegram-bot-api/telegram-bot-api/v5`, long polling |
| Рендер     | `github.com/fogleman/gg` + шрифт Go (`gofont`, есть кириллица)     |
| Подложка   | тайлы OpenStreetMap (256px, Web Mercator), дисковый кэш            |
| FIT        | `github.com/muktihari/fit` — чистый Go, проверка CRC, fuzz-тесты   |

## 3. Термины

- **Заезд (race)** — одна сессия трансляции геопозиции. Идентификатор — целое число,
  пользователю показывается в hex (`id=26` → `1a`).
- **Точка (point)** — координаты + время, полученные от Telegram в рамках заезда.

## 4. Функциональные требования

### 4.1. Запись заезда

1. Пользователь отправляет боту **трансляцию геопозиции** (Live Location).
   Бот получает `message` с `location.live_period > 0`:
   - создаётся новый заезд, привязанный к `(chat_id, message_id)` этого сообщения;
   - если у пользователя уже есть активный заезд — он завершается;
   - первая точка сохраняется;
   - бот отвечает: «🚴 Заезд /race_1a начат».
2. Обновления позиции приходят как `edited_message` с тем же `message_id`.
   Каждое обновление → новая точка в активном заезде.
   Время точки = `edit_date` (для первой — `date`).
3. Заезд завершается, если:
   - пришёл `edited_message` без `live_period` (пользователь остановил трансляцию);
   - истёк срок трансляции (`date + live_period`, + 5 мин запаса) — проверяется фоновой задачей раз в минуту;
   - для бессрочной трансляции (`live_period = 0x7FFFFFFF`) — нет обновлений дольше `IDLE_TIMEOUT` (по умолчанию 2 ч);
   - пользователь начал новую трансляцию.
4. По завершении бот присылает итог: дистанция, длительность, макс. скорость, ссылка-команда на заезд.
5. Обычная (не live) геопозиция не создаёт заезд — бот отвечает подсказкой.
6. Фильтрация шума: точки с `horizontal_accuracy > MAX_ACCURACY_M` (по умолчанию 100 м) не сохраняются.

### 4.2. Загрузка тренировки из .fit

Пользователь присылает боту `.fit` файл документом (часы, велокомпьютер). Бот проверяет файл,
создаёт **завершённый** заезд (`source = 'fit'`) и отвечает
«🏁 Заезд /race_2a загружен из FIT (🏃 бег) + сводка», затем присылает карту. Дальше это обычный
заезд: настройки, видимость, агрегации (в том числе с live-заездами).

Принимаются тренировки любого вида спорта с GPS; вид спорта сохраняется (`sport`) и показывается
значком в `/races` и подписях (🚴 🏃 🚶 🥾 🏊 ⛷ 🛼). Повторная загрузка того же файла тем же
пользователем (совпал SHA-256) не создаёт дубль — бот показывает существующий заезд.

**Проверки файла** (FIT — двоичные данные, которые только читаются и никогда не исполняются;
защищаемся от файлов, пытающихся уронить или перегрузить парсер):
1. имя оканчивается на `.fit`; размер по данным Telegram ≤ 10 МБ — иначе файл даже не скачивается;
   при скачивании читается не больше 10 МБ;
2. заголовок: размер 12 или 14 байт, сигнатура `.FIT`, `заголовок + данные + CRC == размер файла`
   (отсекает обрезанные файлы, мусор в конце и склеенные FIT);
3. CRC заголовка и данных (декодер);
4. разбор с таймаутом 10 с и перехватом паник;
5. тип файла — `activity` (курсы, настройки, мониторинг отклоняются);
6. не больше 100 000 записей; координаты в допустимых пределах и не (0, 0); время не раньше
   эпохи FIT (1989-12-31) и не позже «сейчас + 1 сутки»; минимум 2 точки с GPS
   (записи без координат — до фиксации GPS, в тоннеле — пропускаются).

Сам файл не сохраняется: в БД попадают только извлечённые точки и SHA-256 файла.
Ошибки проверки показываются пользователю понятным текстом («Файл повреждён…», «Это не тренировка…»).
Ссылка на скачивание файла содержит токен бота и никогда не пишется в логи.

### 4.3. Команды

| Команда        | Описание |
|----------------|----------|
| `/start`, `/help` | Инструкция: как начать запись заезда. |
| `/races`       | Список последних 50 заездов пользователя, новые сверху. |
| `/race_<hex>`  | Картинка трека заезда. |
| `/aggregations` | Список агрегаций пользователя (алиасы: `/aggregation`, `/agregation`). |
| `/agr_<hex>`   | Картинка агрегации: все её заезды на одной карте. |

Команды `/races`, `/aggregations`, `/help` бот регистрирует в меню Telegram при старте (`setMyCommands`).

Формат строки списка:
```
/race_1a  23.09.2026 10:15 — 23.09.2026 12:40
/race_1b  23.09.2026 18:02 — идёт
```

> Примечание: в Telegram команда может содержать только `a-z`, `0-9` и `_`,
> поэтому формат `/race-1a` не будет кликабельным — используем `/race_1a`.

Даты выводятся в часовом поясе `TZ` (по умолчанию `Europe/Moscow`).
`/races` показывает только заезды самого пользователя; публичные помечены 🌐.

### 4.4. Видимость и настройки заезда

- У заезда есть видимость: **приватный** (по умолчанию) или **публичный**.
- Приватный заезд открывает только владелец. Публичный — любой, кто знает команду `/race_<hex>`.
  Для чужого/скрытого заезда ответ одинаковый — «Заезд не найден» (нельзя узнать, существует ли он).
- Под картинкой заезда владельцу показываются inline-кнопки **«⚙️ Настройки»** и
  **«🔗 Агрегировать с…»** (см. 4.5); другим пользователям кнопок нет. Нажатие присылает сообщение с настройками:
  ```
  ⚙️ Настройки заезда /race_1a

  Видимость: 🔒 приватный — виден только вам
  [🌐 Сделать публичным]
  ```
  Кнопка переключает видимость; сообщение обновляется на месте, бот показывает всплывающее
  уведомление «Заезд теперь публичный/приватный».
- Кнопка несёт целевое состояние (`pub:1a:1` / `pub:1a:0`), поэтому повторное нажатие ничего не ломает.
- Менять настройки может только владелец; остальным — уведомление «Настройки доступны только автору заезда».
- Правила доступа — функции `canView` / `canEdit` / `canUseAggregation` в `internal/bot/access.go`.

### 4.5. Агрегации

Агрегация — группа из **двух и более** заездов пользователя, которые рисуются на одной карте.
Заезд может входить в любое число агрегаций. Убрать заезд из агрегации или удалить агрегацию —
сами заезды при этом не удаляются.

**Создание.** Кнопка «🔗 Агрегировать с…» под картинкой заезда присылает сообщение-выбор:
до 2 предыдущих (⬅️) и до 2 следующих (➡️) заездов пользователя по времени старта.
Нажатие на заезд создаёт агрегацию из двух заездов, сообщение-выбор заменяется на
«✅ Создана агрегация /agr_3: /race_1a + /race_1b» (чтобы не создать вторую случайно),
и сразу приходит картинка агрегации.

**Картинка агрегации** — та же отрисовка, что у заезда, но:
- кадр строится по всем трекам (центр — центр общего bounding box, 80% / 10% как у заезда);
- у каждого трека свои метки старта и финиша;
- цвет отрезков — по общей шкале от минимальной до максимальной скорости **среди всех треков**;
- в плашке: «Заездов: N», суммарная дистанция, максимальная скорость по всем трекам;
- подпись: `/agr_3 · 3 заезда`, список заездов (до 10, дальше «…и ещё N»), сводка.

Под картинкой — кнопки **«⚙️ Настройки»** и **«➕ Добавить заезд»**.

**Добавление.** «➕ Добавить заезд» предлагает до 2 заездов раньше самого раннего и до 2 позже
самого позднего заезда агрегации (не входящих в неё). Нажатие добавляет заезд и присылает новую картинку.

**Настройки агрегации** — сообщение со списком заездов и кнопками:
- «❌ /race_1a · 23.09 10:15» для каждого заезда — убрать его из агрегации (сообщение обновляется на месте).
  Если в агрегации 2 заезда, убрать нельзя — бот предлагает удалить агрегацию целиком;
- «🔄 Перерисовать» — прислать картинку заново;
- «➕ Добавить заезд» — как выше;
- «🗑 Удалить агрегацию» — удаляет агрегацию (заезды остаются).

**Видимость.** Агрегации пока видны и доступны только владельцу. Публичные агрегации — вне рамок
(агрегация может содержать приватные заезды, для неё нужны отдельные правила).

`/aggregations` — последние 50 агрегаций, новые сверху:
```
/agr_3  3 заезда · 23.09.2026 10:15 — 25.09.2026 19:40
```

**Callback-данные кнопок** (`<действие>:<hex id>[:<аргумент>]`, ≤ 64 байт). Кнопки остаются в чатах
навсегда, поэтому смысл существующих действий не меняется, только добавляются новые:
`set`, `pub` — настройки/видимость заезда; `agp`, `agn` — выбор соседа и создание агрегации;
`aset`, `aadd`, `aput`, `arm`, `adraw`, `adel` — настройки, выбор/добавление, удаление заезда,
перерисовка и удаление агрегации.

### 4.6. Картинка трека

1. **Подложка** — тайлы OSM, кэшируются на диске. В правом нижнем углу — атрибуция «© OpenStreetMap contributors» (требование лицензии OSM).
2. **Кадрирование**:
   - центр карты = центр bounding box трека (в проекции Web Mercator);
   - трек занимает 80% изображения, с каждой из 4 сторон по 10% поля;
   - максимальный размер стороны — 2000 px;
   - выбирается максимальный зум (≤ 18), при котором трек с полями помещается в 2000×2000;
     размер изображения по каждой оси = размер трека / 0.8;
   - минимальная сторона — 400 px (для очень вытянутых/коротких треков поле по короткой оси будет больше 10%).
3. **Линия трека** — отрезки между соседними точками, толщина пропорциональна размеру картинки,
   с тёмной подводкой для контраста. Цвет отрезка зависит от скорости на нём:
   - `v = расстояние(haversine) / Δt`, затем **медианный фильтр по времени**: скорость отрезка —
     медиана скоростей отрезков, чьи середины лежат в пределах ±2 с от его середины.
     На данных 1 Гц (FIT) это ~5 отрезков — убирает «дрожание» GPS (на тестовом FIT максимум
     32.4 → 21.3 км/ч при 20.4 по часам) и сохраняет реальные ускорения; на live-трансляции
     (10+ с между точками) в окне один отрезок — ничего не меняется;
   - дистанция считается по **исходным** точкам (без сглаживания — ближе всего к данным часов);
   - в БД всегда хранятся исходные точки; сглаживание применяется при расчёте, поэтому алгоритм
     можно поменять, и все заезды пересчитаются;
   - `t = (v − v_min) / (v_max − v_min)`;
   - цвет — градиент по оттенку HSV от синего (240°, `v_min`) через голубой/зелёный/жёлтый до красного (0°, `v_max`);
   - если все скорости равны — один цвет из середины градиента.
   - точка отбрасывается, если её время не позже предыдущей принятой точки или если скорость до неё
     выше `MAX_SPEED_KMH` (по умолчанию 120 — сбой GPS); отрезок строится от последней принятой точки.
     Отброшенные точки не рисуются, не влияют на кадрирование и статистику.
4. **Подпись** в левом нижнем углу на полупрозрачной плашке:
   - `Дистанция: 42.31 км`
   - `Макс. скорость: 45.2 км/ч`
   - шкала-градиент с подписями `v_min` / `v_max`.
5. Картинка отправляется как фото (JPEG, q=90), в подписи — дата и статистика.
6. Если в заезде меньше 2 точек — сообщение «Слишком мало точек для построения трека».

## 5. Модель данных

```sql
CREATE TABLE races (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id       INTEGER NOT NULL,
  chat_id       INTEGER NOT NULL,
  message_id    INTEGER NOT NULL,
  started_at    INTEGER NOT NULL,          -- unix, сек
  last_point_at INTEGER NOT NULL,          -- unix, сек
  live_until    INTEGER,                   -- NULL = бессрочно
  finished_at   INTEGER,                   -- NULL = активен
  public        INTEGER NOT NULL DEFAULT 0, -- 1 = виден всем
  source        TEXT NOT NULL DEFAULT 'live', -- 'live' | 'fit'
  sport         TEXT NOT NULL DEFAULT '',     -- вид спорта из FIT
  file_sha256   TEXT,                         -- хэш загруженного файла
  UNIQUE (chat_id, message_id)
);
CREATE INDEX races_user ON races(user_id, started_at DESC);
CREATE UNIQUE INDEX races_user_file ON races(user_id, file_sha256) WHERE file_sha256 IS NOT NULL;

CREATE TABLE points (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  race_id   INTEGER NOT NULL REFERENCES races(id) ON DELETE CASCADE,
  lat       REAL NOT NULL,
  lon       REAL NOT NULL,
  ts        INTEGER NOT NULL,              -- unix, сек
  accuracy  REAL
);
CREATE INDEX points_race ON points(race_id, ts);

CREATE TABLE aggregations (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE TABLE aggregation_races (
  aggregation_id INTEGER NOT NULL REFERENCES aggregations(id) ON DELETE CASCADE,
  race_id        INTEGER NOT NULL REFERENCES races(id) ON DELETE CASCADE,
  PRIMARY KEY (aggregation_id, race_id)
);
```

Дата конца заезда = `last_point_at`.

Миграции — список шагов в `internal/storage`, версия схемы хранится в `PRAGMA user_version`,
при старте применяются недостающие шаги. Уже выкаченные шаги не меняются, только добавляются новые.

## 7. Структура проекта

```
cmd/bot/          — точка входа

internal/config/  — чтение env
internal/storage/ — SQLite, миграции, запросы
internal/geo/     — haversine, скорости (медианный фильтр), статистика трека
internal/fitimport/ — проверка и разбор .fit
internal/render/  — тайлы, кадрирование, отрисовка
internal/bot/     — обработчики Telegram, фоновая задача завершения заездов
deploy/           — скрипт деплоя, настройка сервера, systemd-юнит (см. docs/DEPLOY.md)
.github/workflows — CI: тесты + деплой при пуше в main
```

Тестовые заезды для отладки рендера — `testdata/ride.csv` и `testdata/ride2.csv` (следующий день,
~15 км через Воробьёвы горы, частично совпадает с первым — для проверки агрегаций). `ride.csv` (круг ~10 км Парк Горького — Лужники —
Фрунзенская наб., обновления раз в 10 с, остановка на 1 мин, один сбой GPS, одна точка с повтором времени).

## 8. Нефункциональные требования

- Загрузка тайлов: не более 4 параллельных запросов, дисковый кэш, корректный User-Agent (политика tile.openstreetmap.org).
- Рендер одного заезда ≤ 10 с при прогретом кэше.
- Бот переживает рестарт: активные заезды хранятся в БД, обновления после рестарта продолжают писаться в тот же заезд.
- Юнит-тесты: геометрия/скорости, кадрирование (80%/10%, лимит 2000 px), градиент, хранилище.

## 9. Вне рамок MVP

- Расширение доступа к заездам: друзья, ссылка-приглашение, лента публичных заездов.
- Публичные агрегации; выбор соседних заездов дальше чем ±2 (листание).
- Импорт GPX/TCX; пульс, высота, круги из FIT; упрощение длинных треков (TD-TR).
- Экспорт GPX, высота/набор, сегменты, лидерборды, веб-интерфейс, пагинация `/races`.
